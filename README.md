# Стоматологическая клиника «Улыбка»

Итоговый проект по МДК: информационная система стоматологической клиники на Flutter Web с сервером PocketBase.

Автор: Веников Иван Николаевич, группа П-7-23.

## Что делает система

- Регистратор записывает пациентов на приём, ведёт карты пациентов и принимает оплату в кассе.
- Врач видит свой день, проводит приём и вносит диагноз.
- Новые пользователи могут зарегистрироваться самостоятельно и получают роль регистратора.
- Администратор управляет справочниками, врачами, пользователями и смотрит отчёт по выручке.

Особенности предметной области:

- запись на приём считает длительность и стоимость по выбранным услугам, а скидка постоянного пациента (5 проведённых приёмов — 10 %, 10 — 15 %) рассчитывается на сервере;
- сервер не даёт записать врача, кабинет или пациента на пересекающееся время (ответ 409);
- платежи по приёму не могут превысить его стоимость, отменённый приём не оплачивается;
- расписание показывает занятость врачей по часам и позволяет создать приём щелчком по свободному времени;
- отчёт администратора группирует выручку по врачам, категориям услуг, способам оплаты и дням.

## Сущности и связи

Десять коллекций: users, specializations, cabinets, service_categories, services, doctors, patients, patient_cards, appointments, payments.

- 1:1 — пациент и карта пациента, врач и учётная запись пользователя;
- 1:N — специализация и врачи, кабинет и врач, категория и услуги, пациент и приёмы, врач и приёмы, приём и платежи;
- M:N — приёмы и услуги.

Схема в виде JSON: `docs/pb_schema.json`. SQL-схема: `docs/schema.sql`. Дамп схемы и данных: `docs/database.sql`.

## Запуск

Сервер (нужен бинарный файл PocketBase 0.40.x в каталоге `pocketbase`):

```bash
cd pocketbase
./pocketbase serve --http=127.0.0.1:8090
```

Схема и данные создаются скриптами (Node.js 20+):

```bash
cd pocketbase/setup
node apply-schema.mjs
node load-seed.mjs
node verify.mjs
```

`verify.mjs` выполняет 21 сквозную проверку правил доступа и серверных хуков.

Клиент:

```bash
flutter pub get
flutter run -d chrome --dart-define=PB_URL=http://127.0.0.1:8090
```

## Параметры сборки

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `PB_URL` | адрес сервера PocketBase | `http://127.0.0.1:8090` |
| `DEMO` | `true` — встроенный эмулятор API в браузере, сервер не нужен | `false` |

Публикация на GitHub Pages собирается с `DEMO=true`: приложение работает на эмуляторе серверной части, который повторяет правила доступа, проверки и хуки PocketBase на тех же данных.

```bash
flutter build web --release --base-href /dental_clinic/ --dart-define=DEMO=true
```

## Архитектура

```
lib/
  core/          конфигурация, HTTP-клиент, ошибки API, права доступа, маршрутизатор
  models/        модели предметной области, запрос списка (FilterQuery)
  repositories/  PbRepository и репозитории сущностей
  state/         ChangeNotifier-классы: сессия, списки, формы, карточки, справочники
  screens/       экраны
  widgets/       универсальные список, форма, карточка, фильтры, пагинация
  demo/          эмулятор PocketBase для режима DEMO
pocketbase/      схема, правила, хуки, скрипты наполнения и проверки
docs/            экспорт схемы БД
test/            модульные и виджетные тесты
```

Слои: экран → состояние (ChangeNotifier) → репозиторий → Dio → PocketBase. Экран не обращается к Dio напрямую, репозиторий не знает о виджетах.

## Где принимаются решения о доступе

- Сервер: правила коллекций PocketBase (`pocketbase/setup/apply-schema.mjs`) и хуки (`pocketbase/pb_hooks`). Подмена роли в браузере ничего не даёт: токен и правила проверяются сервером.
- Клиент: матрица `lib/core/access.dart` определяет разделы меню и кнопки, а `lib/core/router.dart` перехватывает переходы по прямым ссылкам и отправляет на страницу 403.
- Роль при запуске заново запрашивается у сервера (`auth-refresh`), поэтому изменённая в хранилище браузера роль исправляется.

## API

Базовый путь `/api/collections/<коллекция>/records`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/api/collections/users/auth-with-password` | вход, ответ `token` и `record` |
| POST | `/api/collections/users/auth-refresh` | обновление токена |
| GET | `/records?page&perPage&sort&filter&expand` | список с поиском, фильтрами, сортировкой и пагинацией |
| GET | `/records/{id}` | запись |
| POST | `/records` | создание |
| PATCH | `/records/{id}` | изменение, в том числе пометка удаления (`deletedAt`) |
| DELETE | `/records/{id}` | полное удаление |

Коды ошибок: 400 — ошибки полей (`data.<поле>.code/message`), 401 — нет или просрочен токен, 403 — нет прав, 404 — запись не найдена, 409 — конфликт (пересечение приёмов, запись со связями, превышение оплаты).

Состояние списков хранится в адресе: `?search=&status=&doctor=&from=&to=&sort=startAt,desc&page=2&size=25`.
